# OmniAPI v1.3.0

桌面版：下載安裝包、執行就能用，不用先裝 Python 或開終端機。另外多了設定頁與模型頁，畫面能排到手機寬度。

## 新東西

- **桌面版安裝包**（Windows，64 位元）
  - 安裝包帶著 Python 與網頁介面，不需要 uv、Python、Node；不需要系統管理員權限，裝在自己的使用者資料夾
  - 系統匣圖示：看得出服務是運作中、啟動中、沒回應還是起不來；選單有開啟看板、重啟服務、開機時啟動、開啟紀錄資料夾、結束
  - 自己的視窗，關掉視窗服務照樣在背景跑（Claude Code 的 MCP 照常能用）；服務不見了會自動拉回來，連續起不來時講原因、列出紀錄檔
  - 開機時啟動：在系統匣選單勾一下，或在設定頁的〈服務資訊〉切換（兩邊是同一個設定）
  - 有新版時，系統匣選單與設定頁會提示並附下載頁（每天最多查一次公開的 Release，不帶任何使用者資料，可以關）
  - 安裝資料夾裡有 `omni.cmd`，終端機指令照樣能用
- **首次啟動引導**：一把 key 都還沒有時，打開看板會帶你選一家供應商、貼 key、測試、存起來；完成時如果等級別名指到你沒有 key 的供應商，會建議改成這一家的模型
- **設定頁**
  - 貼 API key、按「測試」（只請供應商列出模型，不花錢）、存起來就生效，**不用重啟服務**；畫面上只顯示末四碼
  - 每家看得到最近一次列模型或測試的結果（能用、key 無效、沒有餘額……）
  - `cheap`／`standard`／`strong` 等級別名、聊天與派工等六種用途的預設模型，點了就存、立刻生效
  - 服務資訊：版本、資料與作品放在哪、這台電腦找得到哪些外部工具（Node、ffmpeg、Claude Code、Codex、Gemini CLI）
  - 「把 Claude Code 接上」：一鍵把 Claude Code 的 MCP 設定指向這個服務（原有的設定會先備份）
- **模型頁**：每家的模型、價格、能力（看圖、用工具、推理、收 PDF、收音訊）與狀態；30 天內要下架的會提醒，並告訴你設定有沒有用到它
- **畫面適應各種寬度**：寬螢幕、半個螢幕、平板到手機寬度都會重排；窄的時候導覽改成底部分頁列，觸控時較早訊息的動作收進「⋯」
- **MCP**：`list_available_models` 多回各家拿 key 的網址與等級建議值；`tiers` 反映設定頁的修改。等級別名、預設模型在設定頁改了，Claude Code 不用重新連線

## 修正與調整

- 看板的派工表單第一次打開時，預選的模型改用設定頁的「預設派工」（原本固定是 `cheap`）
- `omni run` 不帶 `--model` 時，用設定頁的「預設派工」
- `omni stop` 先請服務自己收尾，15 秒沒結束才強制停止
- 會改東西的請求（例如存 key）只接受來自這台電腦本身的頁面
- 離線沙盒（`OMNIAPI_OFFLINE=1`）啟動時不再向供應商查模型清單
- 紀錄檔 `daemon.log` 會自動輪替

## 下載

| 檔案 | 用途 |
|---|---|
| `OmniAPI_1.3.0_x64-setup.exe` | **桌面版安裝包**。下載後執行 |
| `omniapi-v1.3.0.zip` | 完整版（含已打包好的網頁介面）。解壓後在 `mcp/` 執行 `uv sync`，再 `uv run omni serve` |
| `omniapi-mcp.dxt` | Claude Desktop 擴充。獨立的 stdio 版 MCP server，沒有網頁介面 |

**安裝包沒有程式碼簽章**，第一次執行時 Windows 可能會顯示「Windows 已保護您的電腦」：按「其他資訊」→「仍要執行」。想確認檔案沒被動過，用 `Get-FileHash OmniAPI_1.3.0_x64-setup.exe` 對 `SHA256SUMS.txt`。

## 升級

**繼續用 zip（從 v1.2.0）**

- 換上新版後在 `mcp/` 執行一次 `uv sync`，再重啟服務（`uv run omni stop` 再 `uv run omni serve`）
- 資料庫、`.env` 照舊；設定頁存的值會蓋在 `.env` 之上（`.env` 本身不會被改）
- 已經開著的 Claude Code 要重新連線一次 MCP

**換成桌面版（原本用 zip）**

1. 先停掉舊的服務：在舊的 `mcp/` 執行 `uv run omni stop`
2. 如果設過舊的開機啟動，執行 `uv run omni autostart remove` 拿掉（不拿掉也不會壞，桌面版會提醒）
3. 執行 `OmniAPI_1.3.0_x64-setup.exe`，打開 OmniAPI
4. 兩種裝法用同一個資料夾放資料（`%USERPROFILE%\.omniapi`），聊天、派工紀錄、作品牆、費用都接得上。舊的作品檔案留在原處，作品牆照樣找得到——**舊的 zip 資料夾先不要刪**
5. **key 要重新貼一次**：桌面版不讀 zip 裡的 `mcp\.env`。到設定頁貼上（建議），或把 `.env` 放到 `%USERPROFILE%\.omniapi\.env`
6. 新的作品預設存到「文件\OmniAPI」；要沿用原本的資料夾，見使用指南〈設定〉的〈服務資訊〉
7. Claude Code 的 MCP 位址一樣是 `http://127.0.0.1:7788/mcp`，不用改

桌面版與 zip 不要同時各開一份：它們用同一個埠（7788）。桌面版開的時候如果服務已經在跑，會直接接手，不會起第二份。

## 測過什麼、沒測過什麼

測過（都在一台 Windows 11 上）：

- 全部單元測試；安裝驗證腳本（從零安裝後走一遍：網頁、MCP、聊天、生成、附件、設定 API、外部工具偵測）；聊天、生成、作品、設定四支端到端測試
- 桌面版安裝包：安裝、第一次與之後的啟動（`PATH` 裡沒有 Python、uv、Node 也起得來）、改設定後重開還在、從前一版的安裝包覆蓋升級（服務正在跑的情況下）、解除安裝；安裝測試在暫存資料夾裡做
- 首次啟動引導：在離線的測試環境裡，用假的 key 從頭走到能進聊天
- 發布前的候選安裝包在一台日常使用的 Windows 11 上實際安裝、接上真的 key 用過：系統匣與選單、關視窗後服務還在、開機時啟動、設定頁對各家供應商按「測試」（含 kie.ai 的查點數）、Claude Code 經 MCP 連線，都正常
- 網頁在 1600 到 360 寬之間的畫面與操作（瀏覽器模擬）
- zip 版：解壓到暫存資料夾、`uv sync`、離線測試環境跑安裝驗證與端到端

**沒測過**：

- 沒有在另一台乾淨的電腦上實機安裝過
- 沒有用真的手機或平板試過（畫面寬度是用瀏覽器模擬的）
- 設定頁的「開機時啟動」開關是在上面那次實機安裝之後才加的：服務與網頁的部分在測試環境驗過（寫進系統的值跟系統匣寫的一模一樣），但「系統匣的勾選跟著網頁的修改更新」沒有在實際安裝的桌面版上試過
- 這一版沒有對真的供應商重跑完整的聊天與生成驗收（v1.2.0 跑過的那一套）；真的 key 只試了設定頁的「測試」與日常使用
- SmartScreen 的畫面沒有實際截過圖（說明照 Windows 的一般行為寫）

## 注意

- 只在 Windows 11 上測試過；桌面版只有 Windows 的安裝包
- 桌面版不會自己更新：有新版時會提示，要自己下載新的安裝包、執行覆蓋安裝（設定、key、資料與作品都不會動）
- 畫面能排到手機寬度，但**還不支援從別台裝置連進來**：服務只綁這台電腦
- key 是明文存在你的使用者資料夾裡（`settings.json` 或 `.env`），跟這一版之前一樣
- 用 Claude 派工需要另外安裝並登入 Claude Code；安裝包不附
- 生成、轉錄、聊天會用你自己的 API key 呼叫供應商並產生費用；預估費用是估算，實際以供應商帳單為準
- 服務沒有登入機制，只綁本機；不要把 7788 埠開放到網路上
